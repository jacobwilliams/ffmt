Splitting code lines that are longer than the line length.

A line is split at a token boundary, preferring (in this order) after a comma, after an operator, = or ::, after an opening bracket, and anywhere between two tokens. Within the best kind of break that fits, the rightmost is used. The first part ends with & and the rest goes on a new line; the layout pass then aligns it. Only the code counts: a trailing comment may extend past the limit and moves with the last part. Lines are not split inside tokens (strings in particular), in protected code, in comment or preprocessor lines, or when a token spans lines.

public function split_long_lines(src, line_length, indent, nsplit, changed) result(out)

src with each code line longer than line_length split once. The new continuation lines are indented by indent more than the line they come from if it is the first line of a statement, and like it if it is a continuation line, which the layout pass will usually leave in place. nsplit returns the number of splits.

private pure function stands_alone(source, k)

True if statement k of source, a code statement, can be laid out again on its own after one of its lines is split, giving what laying out the whole text would: it takes up whole lines (no ; before or after it on its lines, no byte order mark), has no statement label (which stays at the start of the line), and is not followed by a comment line that may be lined up with a comment at the end of its last line.
