private function code_signature(src) result(sig)

The code tokens of src as one string that same_code compares when use statements may be reordered: for each token its kind (operators all alike), whether it is glued to the previous token, and its text as key gives it. The signatures of use statements in a run are sorted, and so are those of the items of each only: list.

public pure function longest_code(text) result(width)

An upper bound of the width of the longest code line of text: the characters of each line before a comment, without the blanks before it, as long_code_lines counts them. Preprocessor lines do not count. Strings are followed across continuation lines, so that a ! inside one does not end the code, but the scan does not tokenize, so it may count more than a token-based count would; never less.

private function relayout(text, changed, opts) result(out)

text with the statements at changed (byte ranges, in order) laid out again, each on its own at the column where it starts. text is formatted apart from those statements, and they do not depend on the lines around them (see stands_alone), so this gives what formatting the whole text again would, in a fraction of the time.

public function same_code(a, b, reordered_use, a_tokens)

True if a and b have the same code tokens, in the same order, with the same text and the same joins across line breaks (blanks, comments and line layout may differ). Names and dot operators are compared ignoring case, as Fortran does, and the two spellings of a relational operator (< and .lt.) are the same.

private pure function same_token(sa, s, sb, t)

True if code token s of sa matches code token t of sb, as their keys in code_signature would: same kind (operators all alike), same glue, and the same text, ignoring case where Fortran does (see folded_length), with relational operators in their symbol spelling.

private pure function too_long(text, limit)

True if a code line of text may be longer than limit characters (see longest_code). A line has no more characters than bytes, so the scan is only needed when a line has more bytes than that, which finding the line breaks shows quickly.
